# Project Synchronization

srunx syncs your local project directory to a remote SLURM server using
rsync. This allows scripts that import local modules, read config files, or
reference data to work correctly on the remote side.

## Prerequisites

- rsync installed on both local and remote machines
- SSH key-based authentication to the remote server
- The `srunx` package installed locally

## Sync from the CLI

Mounts (see [Mount Points](#mount-points)) tie a local directory of your
project to a remote one on a cluster. `srunx cluster sync` pushes the mount for
your current directory:

``` bash
srunx cluster sync                               # selected cluster, mount detected from cwd
srunx cluster sync myserver --mount ml-project
srunx cluster sync --dry-run                     # preview only
srunx cluster sync --pull                        # remote -> local (fetch results)
srunx cluster sync --delete --dry-run            # preview what a mirror would remove
srunx cluster sync -e 'data/' -e '*.ckpt'        # extra exclude patterns
```

The cluster defaults to the one commands would target (`--cluster` /
`$SRUNX_CLUSTER` / the project's `cluster` / `default_cluster`), and the
project is discovered from the current directory (or `--project PATH`).

The first sync to a remote path that has not been approved before asks for
confirmation, because a project config (which you may have cloned) decides the
remote path. Pass `--yes` / `-y` to approve it non-interactively. Approved
targets are remembered per cluster in `<state_dir>/approved-sync-targets.json`.

Sync is **additive by default**: it adds and updates files and leaves
destination-only files (checkpoints, job logs, outputs) alone. `--delete`
switches to mirror semantics and removes destination files that are missing
locally. The trade-off is that a file you deleted locally stays on the cluster
and a job can still import it. Over MCP, `inspect_mount` lists those
cluster-only paths without deleting anything.

## Automatic sync on submit

When the script you pass to `srunx sbatch` lives under one of the project's
mounts and the selected cluster is an SSH cluster, srunx:

1. rsyncs that mount to the remote under a per-mount lock,
2. translates the script path to its remote location and runs `sbatch`
   directly on that file (no temporary copy, so the script's own `#SBATCH`
   directives apply),
3. changes into the script's remote directory first, so relative paths such as
   `#SBATCH --output=./logs/%j.out` resolve as expected.

`srunx flow run <yaml> --cluster <name>` syncs each touched mount once and holds
the lock across every job in the workflow. Scripts generated by `--wrap`,
`--template`, or Jinja substitution in a workflow ShellJob are uploaded to
`$SRUNX_TEMP_DIR` instead, because their rendered content has no file in the
mount.

Opt out per run with `--no-sync` (or `--sync` to force it), or set defaults
under `[sync]` in the user config (`$XDG_CONFIG_HOME/srunx/config.toml`):

``` toml
[sync]
auto = true
lock_timeout_seconds = 120
warn_dirty = true
require_clean = false
owner_check = true
verify_remote_hash = false
```

There are no `SRUNX_SYNC_*` environment variables; use the config file or the
per-run flags (`--sync` / `--no-sync` / `--force-sync`).

## Run from a Commit Snapshot

Auto-sync runs the script from the mutable mount when the job *starts*, so a
later sync changes the code under jobs that are still pending or get requeued.
`--snapshot` runs the job from a read-only, per-commit copy of your git
repository on the cluster instead (SSH clusters only):

``` bash
srunx sbatch --snapshot train.sbatch --cluster myserver          # snapshot of HEAD
srunx sbatch --snapshot-rev v1.2.0 train.sbatch --cluster myserver

srunx snapshot create [REV] --cluster myserver   # build only; prints the snapshot path
srunx snapshot list --cluster myserver [--size] [-f json]
srunx snapshot prune --cluster myserver --dry-run
```

- The commit is pushed to a bare repo under the cluster's snapshot root
  (default `~/.local/share/srunx/snapshots`; change it with
  `srunx cluster update <name> --snapshot-root <path>`, outside every
  mount). The cluster needs no GitHub access.
- The job's working directory is the snapshot, and it gets `SRUNX_CODE_DIR` and
  `SRUNX_SNAPSHOT_SHA`. The script is read from the commit, so it does not
  need to be under a mount.
- The snapshot is read-only: pass an absolute `--output` / `--error` (or
  `--log-dir`) and an absolute `-D`, or srunx warns that the job cannot write
  there.
- Validation fails closed: a non-git directory, shallow clone, submodule, LFS
  filter, or tracked changes when the commit is HEAD is rejected (exit 2).
  `--wrap`, `--template`, a local cluster, `--sync`, and `--force-sync` are
  rejected with `--snapshot`.
- `snapshot prune` removes only snapshots that no pending, running, or
  requeue-able job can use (default `--older-than 7d`, minimum `1h`). If the
  scheduler cannot be queried it deletes nothing and exits 1.

## Python API Quick Start

Sync a project via `SSHSlurmClient`:

``` python
from srunx.ssh.core.client import SSHSlurmClient

client = SSHSlurmClient(
    hostname="dgx.example.com",
    username="researcher",
    key_filename="~/.ssh/id_rsa",
)

# Sync local project to remote workspace
remote_path = client.sync_project()
# remote_path = "~/.local/share/srunx/workspaces/myproject/"
```

The project is synced to `~/.local/share/srunx/workspaces/{repo_name}/` on the
remote server. The repository name is detected from `git rev-parse --show-toplevel`.

## Using RsyncClient Directly

For more control, use `RsyncClient` directly:

``` python
from srunx.sync import RsyncClient

rsync = RsyncClient(
    hostname="dgx.example.com",
    username="researcher",
    key_filename="~/.ssh/id_rsa",
)

# Push local directory to remote
result = rsync.push("./my_project", "~/work/my_project/")
if result.success:
    print("Sync complete")
else:
    print(f"Failed: {result.stderr}")

# Pull results back from remote
result = rsync.pull("~/work/my_project/outputs/", "./local_outputs/")
```

## Push and Pull

**push()** syncs a local directory to the remote server:

``` python
result = rsync.push(
    local_path="./src",
    remote_path="~/workspace/src/",
    delete=False,        # Default: keep remote-only files
    dry_run=False,       # Set True to preview without transferring
)
```

- `delete=False` (default): additive. New and changed files are copied;
  files that exist only on the remote are left alone. This is the default
  because remote-only files are typically things a job produced —
  checkpoints, logs, outputs — which by definition do not exist locally.
- `delete=True`: mirror. Remote-only files are deleted. Pair it with
  `max_delete=N` to bound how much a mirror out of a wrong or
  half-populated source directory can remove.
- `max_delete=N` is a blast-radius cap, **not** an atomic refusal. rsync
  deletes up to `N` entries, skips the rest, finishes transferring, and
  only then exits 25 — so when the cap trips, the destination has
  already changed. If you need "refuse without touching anything",
  count the deletions in a separate `dry_run=True` call and decide
  before you push. The MCP `sync_files` tool does this preflight for
  you; a direct `RsyncClient.push()` does not.
- `max_delete` must be `>= 1`. Zero is rejected: `--max-delete=0` means
  *unlimited* on rsync 2.6.x / openrsync, so it cannot be forwarded
  safely. To forbid deletion, leave `delete=False`.
- Directories automatically get a trailing `/` so rsync copies contents,
  not the directory itself.

**pull()** syncs a remote directory to local:

``` python
result = rsync.pull(
    remote_path="~/workspace/results/",
    local_path="./results/",
    delete=False,        # Don't delete local files not on remote (default)
)
```

## Dry Run

Preview what would be transferred without actually syncing:

``` python
result = rsync.push("./src", "~/workspace/src/", dry_run=True)
print(result.stdout)  # Shows file list that would be transferred
```

## Exclude Patterns

By default, common development artifacts are excluded:

- `.git/`, `__pycache__/`, `.venv/`, `*.pyc`
- `.mypy_cache/`, `.pytest_cache/`, `.ruff_cache/`
- `*.egg-info/`, `.tox/`, `node_modules/`, `.DS_Store`

Add custom excludes at initialization or per-call:

``` python
# At initialization (applies to all push/pull calls)
rsync = RsyncClient(
    hostname="host",
    username="user",
    exclude_patterns=["data/raw/", "*.h5", "wandb/"],
)

# Per-call (merged with instance patterns)
result = rsync.push(
    "./project",
    "~/workspace/project/",
    exclude_patterns=["logs/"],
)
```

## ProxyJump Support

If your SLURM server is behind a jump host, pass `proxy_jump`:

``` python
rsync = RsyncClient(
    hostname="dgx-internal",
    username="researcher",
    key_filename="~/.ssh/id_rsa",
    proxy_jump="gateway.example.com",
)
```

This translates to `rsync -e "ssh -J gateway.example.com" ...`.

You can also specify a custom SSH config file:

``` python
rsync = RsyncClient(
    hostname="dgx",
    username="researcher",
    ssh_config_path="~/.ssh/config",
)
```

## macOS Notes

macOS ships with `openrsync` (rsync 2.6.9 compatible), which does not
support `--protect-args` or `--mkpath`. srunx detects this automatically:

- When `--mkpath` is unavailable, remote directories are created via
  `ssh mkdir -p` before syncing.
- When `--protect-args` is unavailable, it is omitted from the rsync
  command.

For full GNU rsync features, install via Homebrew:

``` bash
brew install rsync
```

## Workflow: Sync and Submit

A typical workflow combines sync with job submission:

``` python
from srunx.ssh.core.client import SSHSlurmClient

with SSHSlurmClient(
    hostname="dgx.example.com",
    username="researcher",
    key_filename="~/.ssh/id_rsa",
) as client:
    # 1. Sync project to remote
    remote_path = client.sync_project()

    # 2. Submit job using the synced project (via the SLURM component)
    job = client.slurm.submit_sbatch_job(
        script_content=f"""#!/bin/bash
#SBATCH --job-name=training
#SBATCH --gpus=2
cd {remote_path}
python train.py
""",
        job_name="training",
    )

    # 3. Monitor job
    if job:
        client.slurm.monitor_job(job)

    # 4. Pull results back
    client._rsync_client.pull(
        f"{remote_path}/outputs/",
        "./outputs/",
    )
```

## Mount Points

Mounts are named local-to-remote path mappings of a **project** on a
**cluster**. They decide what `srunx cluster sync` pushes, which scripts are
[synced automatically](#automatic-sync-on-submit) and run in place, and which
roots the Web UI's file browser offers.

They are declared in the project config, `<project root>/.srunx/config.toml`
(meant to be committed; create it with `srunx config init-project`):

``` toml
name = "ml-project"
cluster = "myserver"            # this project's default cluster

[clusters.myserver]
remote_dir = "/home/researcher/projects/ml-project"
exclude = ["data/", "wandb/"]
# sync = false                  # do not rsync the project root

[[clusters.myserver.mounts]]    # extra mounts (optional)
name = "datasets"
local = "../datasets"           # relative to the project root
remote = "/scratch/researcher/datasets"
sync = true
exclude = []
```

- The project root is always a mount, named after the project. It maps to
  `remote_dir`; without `remote_dir` it maps to the remote default workspace
  `$XDG_DATA_HOME/srunx/workspaces/<name>-<hash>` (resolved on the cluster;
  `srunx cluster test <name>` caches the remote directories).
- `remote_dir` and every mount `remote` must be absolute.
- A project config cannot contain connection settings — hosts are defined only
  in your user (or system) config with `srunx cluster add`.
- Personal overrides that should not be committed (for example a different
  `remote_dir` on your account) go in the user config under
  `[projects.<name>.clusters.<cluster>]`.

Set values from the CLI:

``` bash
srunx config set remote_dir /home/researcher/projects/ml-project --cluster myserver --project
srunx cluster show myserver      # connection, defaults, and the project's mounts on it
```

Mounts integrate with the Web UI's DAG builder: when you click the file
browser icon on a path field, the selected project's mounts appear as browsable
project roots. See [Web UI guide](../how-to/webui.md) for details.

## API Summary

| Class / Method | Description |
|----|----|
| `RsyncClient(hostname, username, ...)` | Create an rsync wrapper with SSH connection parameters |
| `RsyncClient.push(local, remote, ...)` | Sync local to remote (additive; no `--delete` unless `delete=True`) |
| `RsyncClient.pull(remote, local, ...)` | Sync remote to local (no `--delete` by default) |
| `RsyncClient.get_default_remote_path()` | Returns `~/.local/share/srunx/workspaces/{repo_name}/` |
| `RsyncResult.success` | `True` if rsync exited with code 0 |
| `SSHSlurmClient.sync_project(...)` | Sync project directory and return remote path |
